## レベル変化の問題

### 問題のルール

- 自分のレベルが高い場合は勝利
- 勝利時は相手レベルの半分を加える
- 自分のレベルが低い場合は敗北
- 敗北時は自分のレベルを半分にする
- 同じレベルなら引き分け
- 小数点以下は切り捨てる

### 完成コード

```js
const fs = require("fs");
const input = fs.readFileSync(0, "utf-8").trim().split(/\s+/);

const n = Number(input[0]);
let crLevel = Number(input[1]);

for (let i = 0; i < n; i++) {
  const opLevel = Number(input[i + 2]);

  if (crLevel > opLevel) {
    crLevel += Math.floor(opLevel / 2);
  } else if (crLevel < opLevel) {
    crLevel = Math.floor(crLevel / 2);
  }
}

console.log(crLevel);
```

### 動作確認

```bash
echo "5 10 5 11 20 8 7" | node.exe battle.js
```

期待する出力：

```text
11
```

### レベルの変化

| 戦闘 | 自分 | 相手 | 結果 | 戦闘後 |
|---:|---:|---:|---|---:|
| 1 | 10 | 5 | 勝利 | 12 |
| 2 | 12 | 11 | 勝利 | 17 |
| 3 | 17 | 20 | 敗北 | 8 |
| 4 | 8 | 8 | 引き分け | 8 |
| 5 | 8 | 7 | 勝利 | 11 |

## `input[i + 2]`の意味

入力：

```text
5 10 5 11 20 8 7
```

配列内では次のようになる。

```text
input[0] = "5"  // 戦闘回数
input[1] = "10" // 最初の自分のレベル
input[2] = "5"  // 1人目の相手
input[3] = "11" // 2人目の相手
input[4] = "20" // 3人目の相手
```

相手のレベルは`input[2]`から始まるため、次を使う。

```js
const opLevel = Number(input[i + 2]);
```

ループごとの変化：

```text
i = 0 → input[2]
i = 1 → input[3]
i = 2 → input[4]
```

`i`は`for`文で宣言しているため、ループ内で使用する。

また、戦闘相手は毎回変わるため、`opLevel`もループ内で取得する。

---

## `const`と`let`

最初は次のように書いた。

```js
const crLevel = Number(input[1]);
```

しかし、自分のレベルは戦闘によって変化する。

そのため、再代入できる`let`を使用する。

```js
let crLevel = Number(input[1]);
```

---

## 計算結果を変数へ保存する

次のコードは計算するだけで、結果を保存していない。

```js
Math.floor(crLevel / 2);
```

計算結果を以降も使用するには、変数へ代入する必要がある。

```js
crLevel = Math.floor(crLevel / 2);
```

---

## `+=`と`=`の違い

### `+=`

現在の値に、右側の値を追加する。

```js
crLevel += 2;
```

これは次と同じ。

```js
crLevel = crLevel + 2;
```

勝った場合は、相手レベルの半分を現在レベルへ追加する。

```js
crLevel += Math.floor(opLevel / 2);
```

### `=`

右側の計算結果で、現在値を置き換える。

```js
crLevel = Math.floor(crLevel / 2);
```

負けた場合は、自分のレベルそのものが半分になるため、`=`を使用する。

```text
勝利：相手の半分を追加する → +=
敗北：自分を半分に置き換える → =
```

## デバッグ出力

配列の中身を確認するときは、コード内に次を書く。

```js
console.log(input);
console.log(input[0]);
console.log(input[1]);
```

確認後、Paizaへ提出するときは削除する。

提出コードに残す出力は、答えだけにする。

```js
console.log(crLevel);
```

余計な出力があると、計算が正しくても不正解になる。

また、次は値の確認ではなく代入になる。

```js
input[0] = 500;
```

値を確認する場合は、次を使用する。

```js
console.log(input[0]);
```

```bash

```

Node.jsは`battle.js~`という別のファイルを探すため、次のエラーになった。


## 次の問題：2つの変数を操作するコンピュータ

コンピュータには2つの変数があり、最初は両方とも`0`。

```text
変数1 = 0
変数2 = 0
```

命令は3種類ある。

| 命令 | 意味 |
|---|---|
| `SET i a` | 変数`i`に`a`を代入する |
| `ADD a` | 変数1と`a`を足し、変数2へ代入する |
| `SUB a` | 変数1から`a`を引き、変数2へ代入する |

### 手作業で確認した例

入力：

```text
4
SET 1 10
ADD 5
SET 1 8
SUB 3
```

最初：

```text
変数1 = 0
変数2 = 0
```

`SET 1 10`実行後：

```text
変数1 = 10
変数2 = 0
```

`ADD 5`実行後：

```text
変数2 = 変数1 + 5
変数2 = 10 + 5
変数2 = 15
```

`SET 1 8`実行後：

```text
変数1 = 8
変数2 = 15
```

`SUB 3`実行後：

```text
変数2 = 変数1 - 3
変数2 = 8 - 3
変数2 = 5
```

最終出力：

```text
8 5
```

### 注意点

`ADD`と`SUB`は、変数2の現在値に足したり引いたりする命令ではない。

必ず変数1を使用して計算し、その結果を変数2へ代入する。

```text
ADD a → 変数2 = 変数1 + a
SUB a → 変数2 = 変数1 - a
```

---

## 今日理解したこと

- ループ内で変化する値は、ループ内で取得する
- 変更する変数には`let`を使う
- 計算しただけでは変数の値は変わらない
- 値を増やす場合は`+=`を使う
- 値を置き換える場合は`=`を使う
- 配列の位置と入力形式を対応させて考える
- デバッグ出力は提出前に削除する
- 命令シミュレーションは、命令を上から順番に実行する
