# 2026-10-20 学習ログ：命令処理とif文の範囲

## 今日やったこと

- `for`ループで命令を1行ずつ読み、半角スペースで分割した。
- SETの処理を修正し、ADD・SUBの処理を個別に書いた。
- 値の追跡よりも、自分でコードを書く練習を中心に進めた。

## 書けたコード

### 命令の読み取りとSETの処理

```js
for (let i = 1; i <= n; i++) {
  const command = lines[i].trim().split(" ");

  if (command[0] === "SET") {
    if (command[1] === "1") {
      variable1 = Number(command[2]);
    } else {
      variable2 = Number(command[2]);
    }
  }
}
```

### ADD・SUBの処理

以下はSETの分岐に続けて組み込む部分。

```js
} else if (command[0] === "ADD") {
  variable2 = variable1 + Number(command[1]);
} else if (command[0] === "SUB") {
  variable2 = variable1 - Number(command[1]);
}
```

※各部分のコードは確認済み。すべてをつなげたループ全体の確認と実行は次回行う。

## 間違えたところと修正

| 間違い | 修正・学んだこと |
| --- | --- |
| `split(" ")`だけを書いた | 分割する対象を付け、`lines[i].trim().split(" ")`にする |
| `split()`と書いた | 引数なしでは命令文が分割されないため、区切り文字の`" "`を指定する |
| SETの直後に`}`を書いた | 変数の代入先を判定するif文を、SETの中に入れる |
| ADDで`variable1`を更新した | 計算結果の代入先は`variable2` |
| SUBの条件を`"SET"`と書いた | `"SUB"`に修正する |
| SUBで足し算をした | 演算子を`-`に修正する |

## 理解したこと

- `{}`の位置によって、if文の処理範囲が決まる。
- if文の`}`を閉じても、次の命令に移るわけではない。同じループ内の次のコードへ進む。
- SETの外に代入先の判定を書くと、ADDやSUBでもその判定が実行されてしまう。
- 存在しない`command[2]`は`undefined`になり、`Number(undefined)`は`NaN`になる。
- `if / else if`でつなぐと、条件に合った命令の処理を選べる。
