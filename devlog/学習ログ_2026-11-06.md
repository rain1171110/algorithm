## 実行時の問題と解決

### 1. 最初の実行で起きた問題

実行コマンドを試したとき、次のようなエラーが出た。

```bash
echo "5 10 5 11 20 8 7" | node battle-review.js
```

表示された内容：

```text
stdin is not a tty
```

これは、Git Bash 上で `node` が `winpty` 経由で起動されている場合に、パイプ入力がうまく渡らないことがあるためだ。

### 2. 実行方法の修正

`node.exe` を直接指定して実行したら、標準入力を正常に受け取れた。

```bash
echo "5 10 5 11 20 8 7" | node.exe battle-review.js
```

### 3. 実行結果

```text

相手:11,更新後: 17
相手:20,更新後: 8
相手:8,更新後: 8
相手:7,更新後: 11
11
```

この出力から、対戦ごとにレベルが更新され、最終的に `11` になっていることが確認できた。

## 自分で書き直したコード

```js
const fs = require("fs");
const input = fs.readFileSync(0, "utf-8").trim().split(/\s+/);

const n = Number(input[0]);
let currentLevel = Number(input[1]);

for (let i = 0; i < n; i++) {
  const opponentLevel = Number(input[i + 2]);
}
```

### このコードの意味

- `n` に対戦回数を入れる。
- `currentLevel` に初期レベルを入れる。
- `i < n` にすることで、対戦回数分だけループする。
- 相手レベルは配列の `2` 番目から始まるので、`input[i + 2]` で順番に取る。
- `Number(...)` で文字列を数値に変換している。

## 今日理解したこと

### 1. 代入の考え方

```js
left = right;
```

これは、「右辺の値を左辺に代入する」という意味だ。

たとえば、

```js
currentLevel = input[1];
```

と書くと、「自分のレベルの元になる値は `input[1]` だ」と明確にできる。

### 2. `for` 文の回数の決め方

```js
for (let i = 0; i < n; i++)
```

この書き方では、`i` が `0` から `n - 1` まで動くので、合計 `n` 回繰り返す。

つまり、対戦回数に合わせて処理を何回も行うときに使いやすい。

### 3. 入力配列の位置

```js
input = [n, currentLevel, opponent1, opponent2, ...]
```

のような並びになっている場合、相手レベルは `input[2]` から始まる。

そのため、ループの `i` に `2` を足して順番に取り出す。

### 4. 標準入力の読み込み方

```js
const input = fs.readFileSync(0, "utf-8").trim().split(/\s+/);
```

これは、

- 標準入力を読み込む
- 前後の空白を消す
- 空白区切りで分割する

という処理をまとめて行う。

### 5. Git Bash での実行注意

パイプ入力を使うとき、`node` ではなく `node.exe` を直接指定すると安定して動く場合がある。

これは、Windows 環境での実行差分によるもの。今後も、標準入力を使うときはこの点を意識しておくとよい。

## ここまでの整理

今日は、入力の読み取りとループの考え方はかなり整理できた。

特に大事なのは次の2つだ。

- `input[0]` で対戦回数
- `input[1]` で初期レベル
- `input[i + 2]` で相手レベルを順番に取り出す

という流れ。
